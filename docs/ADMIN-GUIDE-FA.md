# راهنمای مدیر سامانه

## سلامت سیستم و بکاپ

صفحهٔ «سلامت سیستم» فقط برای مدیر است و نسخهٔ برنامه و schema، اتصال DB، حالت
نگهداری و فضای آزاد داده/بکاپ را نشان می‌دهد. از بخش «تاریخچهٔ بکاپ» می‌توان
ساخت آرشیو تازه را آغاز کرد؛ کار در پس‌زمینه ادامه می‌یابد و پس از verify، دکمهٔ
دریافت فقط برای فایل معتبر فعال است. فایل خراب نمایش داده می‌شود اما قابل دریافت
نیست. دکمهٔ «بازیابی» پس از هشدار روشن و واردکردن واژهٔ تأیید، handoff امن را
ثبت می‌کند؛ سرویس کوتاه‌مدت متوقف می‌شود، بکاپ ایمنی می‌سازد و بازیابی را پیش از
بالا آمدن وب انجام می‌دهد. برای اتوماسیون همین گردش از CLI نیز در دسترس است.

## کاربران و نقش‌ها

مدیر می‌تواند کاربر داخلی بسازد، نقش یا وضعیت او را تغییر دهد. «طراح فرم» پروژه را می‌سازد، ویرایش و منتشر می‌کند و پاسخ/گزارش را می‌بیند. «مشاهده‌گر» فقط خواندن و خروجی دارد. سامانه غیرفعال‌کردن آخرین مدیر و حذف دسترسی مدیر از نشست خودش را رد می‌کند.

## پروژه و فرم

هر پروژه یک پیش‌نویس، نسخه‌های انتشار‌یافتهٔ تغییرناپذیر و پاسخ‌های وابسته به همان نسخه دارد. «نمای کلی» برای وضعیت و میانبرهاست؛ دکمهٔ بازگشت به فهرست پروژه‌ها مستقل است. در «ساخت فرم» صفحه و فیلدها را بسازید، سپس در «مسیرها» fallback و شرط‌ها را تعیین و اعتبارسنجی انتشار را اجرا کنید.

slug پس از نخستین انتشار ثابت است تا نشانی عمومی شکسته نشود. بستن پروژه پاسخ تازه را متوقف می‌کند ولی داده و گزارش باقی می‌ماند. انتقال به زباله‌دان وضعیت قبلی را نگه می‌دارد تا restore همان حالت را برگرداند.

## پاسخ و گزارش

پاسخ‌ها بر اساس snapshot نسخه نمایش داده می‌شوند. تاریخ‌ها در رابط شمسی و در DB به UTC/Gregorian هستند. حذف پاسخ نرم است و مدیر می‌تواند آن را بازیابی کند.

در گزارش، فیلتر نسخه و بازه روی ترافیک و پاسخ اعمال می‌شود. فیلتر پایان یا مقدار فیلد فقط پاسخ‌های تکمیل‌شده را segment می‌کند؛ بازدید، شروع و فعالیت صفحه قابل انتساب قطعی به پاسخ نهایی نیستند و رابط این تفاوت را صریح نشان می‌دهد. برای آرشیو اداری از چاپ A4 یا CSV/XLSX/JSON استفاده کنید.

## انتقال پروژه

بستهٔ پروژه draft و نسخه‌های انتخابی را با checksum منتقل می‌کند و پاسخ/فایل پاسخ‌دهندگان را شامل نمی‌شود. همیشه preview import را ببینید و title/slug مقصد تازه را تعیین کنید. بستهٔ پروژه جای backup کامل را نمی‌گیرد.

## دستیار داده

این قابلیت اختیاری است و نبود provider یا مدل روی فرم‌ساز، انتشار و دریافت پاسخ اثری ندارد. مدیر provider را در تنظیمات پروژه ثبت و «آزمون اتصال» را اجرا می‌کند؛ ذخیره به‌تنهایی هیچ درخواست خارجی نمی‌فرستد. آزمون ناموفق اتصال را آماده نشان نمی‌دهد و تنظیمات یا کلید ذخیره‌شده را جایگزین نمی‌کند.

هر پروژه رضایت جداگانه دارد. حالت پایه فقط schema و aggregation را می‌فرستد؛ نمونه‌خوانی متن آزاد مستقل و هشدار‌دار است. تاریخچهٔ هر کاربر خصوصی و قابل حذف است. دستیار read-only است و پاسخ آن باید به‌عنوان تحلیل کمکی، نه منبع قطعی تصمیم حساس، استفاده شود. جزئیات مرز داده و نحوهٔ گزارش امن در [سیاست امنیت](SECURITY.md) آمده است.

## زباله‌دان و عملیات

زباله‌دان پروژه‌ها فقط برای مدیر است. «سلامت سیستم» نسخهٔ برنامه/schema، وضعیت نگه‌داری، فضای data/backup و آخرین backup ثبت‌شده را نشان می‌دهد. پنل و CLI هر دو فقط handoff را آغاز می‌کنند؛ خود restore عمداً در systemd و خارج از process وب انجام می‌شود.

## مرجع کوتاه CLI

راهنمای خط فرمان به پایگاه‌داده یا فایل تنظیمات نیاز ندارد:

```bash
forms --help
forms admin --help
forms backup --help
forms restore --help
```

فرمان‌های مدیریتی اصلی عبارت‌اند از:

- `forms admin create` و `forms admin reset-password` برای حساب مدیر؛
- `forms migrate status|up` برای schema؛
- `forms backup create|verify|list|prune` برای چرخهٔ بکاپ؛
- `forms restore verify|prepare|apply|pending` برای بازیابی آفلاین؛
- `forms cleanup` برای دادهٔ موقت و `forms doctor` برای کنترل آمادگی.

خروجی فرمان‌های مناسب اتوماسیون JSON است. عملیات مخرب بازیابی به `--confirm`
و سرویس متوقف نیاز دارد؛ برای اجرای production، environment را دقیقاً مانند
واحد systemd بارگذاری کنید.
